SSE Streaming Responses

Server-Sent Events (SSE) responses stream events to clients over a long-lived HTTP connection. This is the transport used by MCP's Streamable HTTP protocol and many other AI APIs.

By default each event's data is a fixed string. To generate event content dynamically — for example to echo a value from the request into every event — set an optional templateType (VELOCITY, MUSTACHE or JAVASCRIPT) on the httpSseResponse. Each event's data is then rendered as a response template against the triggering request, with the same context available in response templates (request fields, jsonPath, built-in helpers, faker and scenario state). When templateType is not set, events are sent exactly as written.

An event's comment is sent before its other fields as a comment line: a : followed by the comment exactly as written, so "heartbeat" is sent as :heartbeat and " heartbeat" (with a leading space) as : heartbeat. A comment with several lines is sent as one comment line per line. Clients ignore comments, so an event with only a comment sends a heartbeat (the comment line and a blank line) that keeps the connection busy without dispatching an event. Events without a comment are sent exactly as before. For NDJSON, JSON array and AWS event-stream LLM responses, which have no comments, an event with only a comment is not sent but its delay is still waited.

Mock WebSocket endpoints that perform the upgrade handshake and send a sequence of text or binary messages. Useful for testing clients that connect to WebSocket APIs (GraphQL subscriptions, real-time feeds, etc.).

As with SSE, text messages can be generated dynamically by setting an optional templateType (VELOCITY, MUSTACHE or JAVASCRIPT) on the httpWebSocketResponse: each text message is then rendered as a response template against the triggering request. Binary messages are always sent verbatim, and with no templateType every message is sent exactly as written.

When withStreaming() is set the agent card reports capabilities.streaming: true. The builder generates an SSE expectation for the streaming JSON-RPC method (default message/stream; legacy tasks/sendSubscribe when overridden). The SSE stream emits three events:

  1. A TaskStatusUpdateEvent with status.state: "working" and "final": false
  2. A TaskArtifactUpdateEvent carrying the configured response text as a text part
  3. A TaskStatusUpdateEvent with status.state: "completed" and "final": true

Each SSE event's data is a JSON-RPC 2.0 response envelope. Use withStreamingMethod(String) to override the JSON-RPC method name — calling this implies withStreaming().

withPushNotifications(webhookUrl) does two things:

  • The agent card reports capabilities.pushNotifications: true.
  • A tasks/pushNotificationConfig/set expectation is created that echoes the registered push-notification config back as the JSON-RPC result.
  • The tasks/send expectation is replaced by an override-forwarded-request that both POSTs the completed task (as a JSON-RPC push payload) to the webhook URL and returns the standard JSON-RPC task response to the original caller.

The webhook URL must be an absolute HTTP or HTTPS URL (e.g. http://localhost:9999/a2a/callback).
