Extension Configuration:

Extensions are your own Java classes that MockServer loads when it starts. See Extensions for how to write and load one. These properties can only be set before MockServer starts (system property, environment variable, properties file or startup configuration); PUT /mockserver/configuration ignores them with a warning, so the control plane can never load code into MockServer.

Comma-separated names of the extension classes to load and start, in addition to any passed in Java code. Each class must implement org.mockserver.extension.Extension, have a public no-argument constructor, and be on MockServer's classpath. If a class cannot be loaded or fails to start, MockServer refuses to start.

Type: string Default: "" (no extensions)

Java Code:

ConfigurationProperties.extensions(String classNames)

System Property:

-Dmockserver.extensions=...

Environment Variable:

MOCKSERVER_EXTENSIONS=...

Property File:

mockserver.extensions=...

Command Line:

--extensions com.example.AuditExtension

Example:

-Dmockserver.extensions="com.example.AuditExtension,com.example.SeedExtension"

When enabled, MockServer also loads every extension listed in a META-INF/services/org.mockserver.extension.Extension file on its classpath, and logs the JAR each one came from. Off by default, so only the extensions you name are loaded; turn it on only when you control every JAR on the classpath.

Type: boolean Default: false

How long MockServer waits, in milliseconds, for each extension's start, onStarted and stop to return. If start or onStarted takes longer, MockServer refuses to start. Values below 1 are treated as 1.

Type: long Default: 30000

Environment Variable:

MOCKSERVER_EXTENSION_START_TIMEOUT_MILLIS=...

Property File:

mockserver.extensionStartTimeoutMillis=...

Example:

-Dmockserver.extensionStartTimeoutMillis="60000"

The most calls to extension admin routes (paths under /mockserver/extensions/<name>/) that MockServer runs at once. A call beyond this is answered 503 Service Unavailable with a Retry-After: 1 header; this is logged at most every 10 seconds and, when metrics are enabled, counted by mock_server_overload_rejections with reason="extension_admin". A call keeps its place until the extension's code returns, even after it timed out, so a stuck extension cannot make MockServer start more and more threads. Values below 1 are treated as 1.

Type: int Default: 32

Java Code:

Environment Variable:

MOCKSERVER_EXTENSION_ADMIN_MAX_IN_FLIGHT=...

Property File:

mockserver.extensionAdminMaxInFlight=...

Example:

-Dmockserver.extensionAdminMaxInFlight="8"

How long MockServer waits, in milliseconds, for an extension admin route to answer. If it has not answered by then, MockServer answers 500 itself, interrupts the extension's code and discards whatever it returns later. Not applied when MockServer runs as a WAR, where the extension runs on the servlet container's request thread. Values below 1 are treated as 1.

Type: long Default: 30000

How many events each listener extension can have waiting while it catches up. Each listener runs on its own thread, so a slow listener never slows MockServer down; once its queue is full, further events for it are dropped and counted in the mock_server_extension_listener_dropped_total metric, and a warning is logged once. Raise it if a listener falls behind during bursts. Values below 1 are treated as 1.

Type: int Default: 10000

Java Code:

ConfigurationProperties.extensionListenerQueueSize(int size)

System Property:

-Dmockserver.extensionListenerQueueSize=...

Environment Variable:

MOCKSERVER_EXTENSION_LISTENER_QUEUE_SIZE=...

Property File:

mockserver.extensionListenerQueueSize=...

Example:

-Dmockserver.extensionListenerQueueSize="50000"

The most data, in bytes, that events waiting for ServeEventListener and ExpectationLifecycleListener extensions may hold: the requests and responses of served-request events, and the expectations that expectation changes refer to. It is split equally between those listeners, so one that stops reading can only fill its own share; events that do not fit are dropped and counted. This keeps listeners from running MockServer out of memory even with large bodies or large expectations. Bodies in these events are already cut to maxLoggedBodyBytes when that is set. Values below 1 use the default.

Type: long Default: about 5% of the maximum heap (16 MB when the heap has no limit)

The total time, in milliseconds, that one response or forward template waits for the template helpers it calls from extensions. Every helper call in one template shares this budget, so a template that calls a slow helper in a loop still finishes in time. A call still running when the budget is used up is interrupted and the template fails. Values below 1 are treated as 1.

Type: long Default: 1000

MOCKSERVER_EXTENSION_HELPER_TIMEOUT_MILLIS=...

Property File:

The most extension template helper calls that run at the same time. A template whose helper call would go over this limit fails at once rather than waiting, so a helper that hangs turns into fast template failures instead of piling up threads. Values below 1 are treated as 1.

Type: int Default: 32

Java Code:

System Property:

-Dmockserver.extensionHelperMaxInFlight=...

Environment Variable:

MOCKSERVER_EXTENSION_HELPER_MAX_IN_FLIGHT=...

Property File:

mockserver.extensionHelperMaxInFlight=...

Example:

-Dmockserver.extensionHelperMaxInFlight="64"

How long, in milliseconds, the request filters for one request may take together, and likewise the response transformers for one response, so a request can wait up to twice this in all. A filter or transformer still running when the time is up is interrupted and fails: the request is answered 500, unless that extension and every one after it in the chain fail open, when the request or response carries on as it was before that extension ran. A gRPC call's grpc-timeout includes this time. Keep twice this value well below inboundConnectionIdleTimeoutMillis and stopDrainMillis; MockServer logs a warning at start-up when it is not. Values below 1 are treated as 1. It can only be set at start-up.

Type: long Default: 1000

Java Code:

ConfigurationProperties.extensionDataPlaneTimeoutMillis(long millis)

System Property:

-Dmockserver.extensionDataPlaneTimeoutMillis=...

Environment Variable:

MOCKSERVER_EXTENSION_DATA_PLANE_TIMEOUT_MILLIS=...

Property File:

mockserver.extensionDataPlaneTimeoutMillis=...

Example:

-Dmockserver.extensionDataPlaneTimeoutMillis="250"

The most request filter and response transformer runs that happen at the same time; filters and transformers share this limit. A request that would go over it is answered at once with 503 Service Unavailable and a Retry-After: 1 header, rather than waiting, unless every extension involved fails open, when they are skipped. Refusals are counted by mock_server_overload_rejections with reason="extension_dataplane" when metrics are enabled. A run keeps its place until the extension's code returns, even after it timed out, so a stuck extension turns into fast 503 responses instead of more and more threads. Values below 1 are treated as 1. It can only be set at start-up.

Type: int Default: 32
